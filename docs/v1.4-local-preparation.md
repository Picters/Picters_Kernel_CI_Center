# Picters 1.4 local preparation

The user authorized a local Android 17 testing build on 2026-10-31, followed by
source commits/pushes under Picters. No workflow dispatch or release publication
is authorized. README files are excluded from these source commits.

Prepare changes for both Android 16 and Android 17. The requested eventual
delivery is Android 17 only and consists of three files:

- signed mobile-only arm64-v8a Picters manager APK;
- matching Mi17_Kernel ZIP;
- matching Mi17_PictersKernelPack ZIP containing that same APK and kernel's modules.

## Existing local source changes

- PictersKernelPack replaces the old OOT archive filename; the internal module ID,
  and description remain as before; the display name is now PictersKernelPack.
- The vendor vermagic/KMI guard replaces an Android system SDK installation gate.
  Modules still require the exact running kernel release.
- Boot service PMM_PERF_V2 supports saved performance governors and independent
  minimums, including snapshot restoration and the shared app/service mutex.
- APK is pinned locally with a SHA-256; the published 1.3.2 pin remains untouched
  until a new signed 1.4 phone APK is built and approved for packaging.
- Kernel source includes independent CPU frequency floors and capability discovery;
  performance governor options are enabled without changing the boot governor.

## Packaging sequence, after build authorization

1. Build the phone app using its production `lib/main.dart` entry point and
   `--target-platform=android-arm64`. The desktop entry point must not be used.
2. Verify the ABI, package version/code and release signing certificate. Stage
   the exact signed APK in `assets/PictersModulesManager.apk` and update its SHA.
3. Use an isolated snapshot that includes ALL local kernel changes. The existing
   CLI now has --kernel-checkout to snapshot that branch plus tracked/untracked
   edits, without changing it or creating a commit. Use a fresh local root;
   existing destinations, branch changes and unsupported submodules are refused.
   For A17, select android_kernel_xiaomi_sm8850-extra-android17 on android17.
4. Build the selected kernel and OOT drivers against the same config/toolchain,
   then package both archives with the same kernel release and build date.
5. Inspect the three final files, manifest, module pairing and APK checksum before
   handing them to the user. Nothing is uploaded or published automatically.

Thermal policy editing/crypto is application code, not a reason to disable kernel
thermal zones or charging protection in PictersKernelPack. The new thermalctl.sh helper handles file installation and restoration,
with boot/uninstall hooks. Its file transactions and app transport have fixture
tests; actual phone activation/thermal behavior remain unverified. The thermal gate uses the captured loader hash and matching pack/kernel API,
without a manual verified-device record. This does not establish device behavior.
Charging source now includes a leased MCA normal-vote adapter, exact vendor CRC
imports, guarded root policy worker, app transport, Off/restore and persistence.
Its W value is an approximate target, not a guaranteed adapter input cap.
Both kernel build paths compile the adapter, but runtime is gated to the captured
MCA binaries; different Android 16 vendor binaries are not implicitly supported.
Rust compilation and all 13 Rust tests passed. The signed arm64 Android APK
was built and its existing Picters certificate verified. Kernel/adapter compilation
and packaging are in progress. No additional phone test runs are requested.
